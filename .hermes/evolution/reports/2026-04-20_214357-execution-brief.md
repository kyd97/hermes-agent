# Hermes Evolution Execution Brief
## Chosen slice
**A1 — Wire pre-compression memory hints into compression summaries**

Implement the missing handoff between `MemoryManager.on_pre_compress()` and the context-compression summarizer so provider-generated preservation hints actually shape the generated summary.

## Why now
This is the best next one-session slice because it is the smallest high-leverage gap among the current P0/P1 items:

- **The scaffold already exists, but the value is currently dropped.**
  - `agent/memory_manager.py` already aggregates provider hints via `on_pre_compress()`.
  - `run_agent.py` already calls `self._memory_manager.on_pre_compress(messages)` during `_compress_context()`.
  - But the returned string is ignored, so A1's intended outcome is not yet achieved.
- **The implementation surface is tightly bounded.**
  - `agent/context_compressor.py` owns the summary prompt and can accept an extra hint payload without forcing a larger architectural decision.
- **Other near-term items are less session-sized right now.**
  - **A2** has hook infrastructure in `MemoryManager`, but `run_agent.py` does not call `on_turn_start()` yet; deciding the exact cadence/context payload is a broader loop-level change.
  - **B1** already loads `.hermes.md`, but only strips frontmatter and injects the markdown body; honoring structured fields implies prompt-contract design for preferred skills / verification / workflow presets.
- **It unlocks later memory work.**
  - A1 makes memory providers materially useful during compaction, which reduces data loss and creates a stronger base for A2–A5.

Current P0/P1 snapshot that informed this choice:
- **A1:** partial scaffold present, not functionally complete.
- **A2:** manager hook exists; main loop wiring missing.
- **B1:** `.hermes.md` discovery exists; structured frontmatter is not honored yet.
- **A3/A4/A5/B2/B3/C1/C2/C3/C4:** still mostly planned/partial; several have broader schema or cross-platform implications than A1.

## Files to touch
1. `run_agent.py`
   - Capture the return value from `self._memory_manager.on_pre_compress(messages)` inside `_compress_context()`.
   - Pass that value into the compressor instead of dropping it.

2. `agent/context_compressor.py`
   - Extend `compress()` and `_generate_summary()` to accept optional pre-compression memory hints.
   - Inject those hints into the summarizer prompt in a clearly bounded section such as "Memory Preservation Hints".
   - Keep the hints contextual/reference-only so they improve preservation without becoming active instructions.
   - Ensure empty / whitespace-only hints are ignored.

3. `tests/agent/test_context_compressor.py`
   - Add/extend tests proving `_generate_summary()` includes preservation hints in the LLM prompt.
   - Add/extend tests proving `compress()` forwards the hint argument through to `_generate_summary()`.
   - Add a no-op case showing empty hints do not change prompt construction.

4. `tests/agent/test_memory_provider.py` *(optional but likely worthwhile)*
   - Keep manager-level coverage minimal if needed, but only touch this file if an explicit integration assertion around `on_pre_compress()` forwarding is helpful.

- Existing focus-topic behavior continues to work alongside memory hints.
- Summary output still uses the current compaction prefix/format.

## Risks / prerequisites
- **Prompt-shaping risk:** preservation hints must be framed as background guidance, not as new instructions that could distort the summary.
- **API-surface risk:** changing `compress()` / `_generate_summary()` signatures requires updating all internal call sites and tests cleanly.
- **Failure-mode handling:** if providers raise or return junk, the existing best-effort behavior should remain intact.
- **Scope control:** avoid expanding this slice into broader memory-manager unification (A3) or turn-start wiring (A2).
